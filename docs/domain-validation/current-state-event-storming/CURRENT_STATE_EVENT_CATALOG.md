# Catálogo de eventos del Current State

**Estado:** Borrador para validación interdisciplinaria.
**Propósito:** Catalogar hechos observables del recorrido actual y separar los hechos humanos de los registros técnicos y de las intenciones futuras.
**Alcance:** Eventos comerciales, operativos y de sistema desde consulta hasta reingreso o posible garantía.
**Fuente:** Product Owner; auditorías legacy; catálogo canónico de eventos y preguntas de dominio.
**Audiencia:** Product Owner, operaciones, técnicos, finanzas, seguridad y arquitectura.
**Última actualización:** 2026-07-14.

## Criterios

- Todos los nombres describen algo que ya ocurrió; el disparador puede ser un comando, una decisión humana o una mutación anterior.
- “Relacionado” significa afinidad semántica, no equivalencia ni aprobación del evento canónico.
- Un hecho humano confirmado puede carecer de timestamp o registro técnico.
- Los cuatro eventos deseados se mantienen en una sección separada y no forman parte del Current State confirmado.

## Conflicto documental relacionado

Una auditoría previa afirmó doble consulta al endpoint de impresión y posible alteración del pago; la auditoría específica del detalle, contra el mismo corte indicado, observó una sola llamada. Ningún evento adicional se crea a partir de esa afirmación. El asunto permanece `Conflict` y debe resolverse reproduciendo el código/ruta exactos antes de atribuir una consecuencia operativa.
