## Problema

Si las fricciones del sistema anterior no quedan registradas con neutralidad, SR Taller 2.0 puede repetirlas o rechazar prácticas valiosas sin entender su contexto.

## Valor esperado

Convertir experiencia previa en restricciones y prácticas comprobables para arquitectura, entrega y migración.

## Alcance

- Registrar contexto, aciertos, fricciones, riesgos, deuda, lecciones y prácticas a conservar/evitar.
- Tratar migración como pregunta, no como copia automática.
- Incluir todas las lecciones solicitadas sobre capas, tenant, realtime, UI, endpoints, async y despliegue.

## Fuera de alcance

- Descalificar personas o decisiones pasadas.
- Auditar código legacy, copiarlo o aprobar una migración.

## Criterios de aceptación

- [ ] [LEGACY_SR_TALLER_LESSONS.md](../../product/LEGACY_SR_TALLER_LESSONS.md) contiene las secciones y lecciones requeridas.
- [ ] Hechos observados se separan de inferencias.
- [ ] Cada lección tiene implicación práctica para 2.0.
- [ ] Preguntas de migración quedan abiertas.
- [ ] Stakeholders con conocimiento histórico revisan el documento.

## Dependencias

Contexto proporcionado y, si se autoriza, revisión humana de participantes del sistema anterior.

## Riesgos

Sesgo retrospectivo; trasladar soluciones sin validar; confundir deuda con falta de valor.

## Preguntas abiertas

- ¿Qué prácticas o datos legacy tienen evidencia suficiente para conservarse?
- ¿Qué obligaciones reales existen sobre migración y continuidad?

## Evidencia esperada

Documento revisado con fuentes/contexto y lista de preguntas de migración.
