# PBI-025 — PIN Credential Authentication

## Estado

- **Sprint:** candidato posterior de Sprint 01; no autorizado.

## Objetivo

Verificar que la identidad seleccionada en una Station confiable conoce su PIN
tenant-scoped, sin convertir el PIN en identidad, capability o sesión.

## Contrato aprobado

- UX `seleccionar User → ingresar PIN`.
- PIN numérico de seis dígitos.
- Credencial separada de User, nunca plaintext ni reversible.
- Salt individual, versión y parámetros gobernados.
- Cinco intentos fallidos consecutivos y lock inicial de cinco minutos.
- Rate limiting adicional por Station/User.
- Reset sensible mediante capability específica y auditoría.
- Reset/revoke invalida sesiones activas del User.

El algoritmo y parámetros concretos se seleccionan mediante threat model y
revisión de seguridad; no se fijan por intuición en este PBI.

## Fuera de alcance

- Operational Session, que pertenece a [PBI-034](./PBI-034.md).
- Roles/capabilities y autorización.
- Email/password, recuperación externa, biometría o identidad global.
- UI administrativa completa, deploy o credenciales productivas.

## Dependencias

- [PBI-024](./PBI-024.md), [PBI-029](./PBI-029.md),
  [PBI-032](./PBI-032.md) y threat model aprobado.

## Criterios de aceptación

- PIN protegido, limitado al Tenant y nunca registrado.
- Respuestas y logs no permiten enumeración útil.
- Intentos, lock, concurrencia, reset y revocación se prueban server-side.
- El resultado autenticado todavía no concede una acción de negocio.
