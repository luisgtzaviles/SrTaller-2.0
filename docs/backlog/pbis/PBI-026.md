# PBI-026 — Contextual Authorization

## Estado

- **Estado:** Selected candidate; not started.
- **Tipo:** Authorization / Security Foundation.
- **Owner:** Producto + Seguridad + Arquitectura + Ingeniería.
- **Riesgo:** crítico.
- **Estimación:** TBD.
- **Sprint:** SPRINT-02 — siguiente candidato seleccionado; no iniciado.

## Objetivo

Autorizar server-side cada operación mediante actor, acción, recurso,
capabilities y scope aplicable al Tenant/Branch resuelto por Station, con
`DENY BY DEFAULT`.

## Alcance

- Roles tenant-scoped y múltiples roles por User.
- Assignments `TENANT_WIDE` o `BRANCH_RESTRICTED`.
- Unión de capabilities aplicables al contexto actual.
- Capabilities específicas por acción; el nombre del role no concede autoridad.
- Revocación efectiva y casos allow/deny/cross-tenant.
- Catálogo inicial de acciones implementadas, reconciliado por slice.

## Fuera de alcance

- Permisos directos al User, deny rules particulares, herencia compleja o ABAC general.
- Reautenticación y segundo aprobador, que pertenecen a [PBI-035](./PBI-035.md).
- Capabilities especulativas de módulos todavía no materializados.

## Dependencias

- [PBI-024](./PBI-024.md), [PBI-033](./PBI-033.md),
  [PBI-034](./PBI-034.md) y contexto de recurso por cada slice.

## Criterios de aceptación

- Sin capability aplicable, la operación falla cerrada.
- IDs de contexto enviados por el cliente no cambian autoridad.
- Roles de otro Tenant o scope de otra Branch son rechazados.
- Revocación y cambios de assignment tienen efecto verificable.
- UI oculta/deshabilitada no sustituye enforcement server-side.

## Próxima revisión

Después del cierre efectivo de PBI-034: refinar el catálogo exacto, estimar,
completar DoR y confirmar la autoridad aplicable del Identity Master Goal.
Selección no equivale a inicio.
