# PBI-024 — Apply trusted tenant, branch and station context

## Estado

- **Estado:** Draft — refinement authorized; implementation not authorized.
- **Tipo:** R0 technical foundation / Security.
- **Owner:** Arquitectura + Ingeniería; revisión Producto + Seguridad.
- **Riesgo:** alto.

El
[tratamiento temporal de DEC051-C02](../../architecture-readiness/pbi-024/DEC_051_C02_TEMPORARY_TREATMENT.md)
permite completar el refinamiento y realizar revisión formal. No cambia este
PBI a `Ready` o `In progress`, no autoriza implementación, rama, commits o PR
funcionales y mantiene bloqueado el primer merge funcional.

## Objetivo

Aplicar ADR-004/010 para resolver un contexto inmutable de tenant, sucursal y
estación desde fuentes del servidor y fallar cerrado ante ausencia, conflicto,
manipulación, revocación o cambio.

## Alcance y exclusiones

Incluye DEC-009–012, vinculación/revocación mínima, propagación y pruebas
negativas. Excluye PIN, sesión de usuario, roles, UI, wildcard, negocio y
offline.

## Dependencias

PBI-023, ADR-004/010, DEC051-C04 y DEC063-C06. No puede comenzar mientras
PBI-023 no demuestre scope tenant persistente.

## Criterios de aceptación

- Contexto server-side inmutable y sin fuente cliente autoritativa.
- Ausencia/conflicto/manipulación fallan cerrados.
- Estación vinculada determina sucursal y revocación invalida contexto.
- Cambio exige desvinculación/revinculación y evidencia.
- Casos con dos tenants y dos sucursales pasan sin enumeración.
- No se implementa identidad/PIN ni negocio.

## Evidencia y gates

Matriz allow/deny, lifecycle, tests integrados, mutaciones críticas, manifest
DEC-063 y gates canónicos.

## Próxima revisión

Refinar contratos, riesgo, estimación, matrices, pruebas y evidencia; después
someter el PBI a revisión formal para decidir por separado si puede pasar a
`Ready` y recibir autorización de implementación.
