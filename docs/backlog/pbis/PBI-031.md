# PBI-031 — Station Binding Administration

## Estado

- **Estado:** Draft; diferido después del runtime context mínimo.
- **Tipo:** Identity & Context Administration / Security.
- **Owner:** Producto + Seguridad + Operaciones + Ingeniería.
- **Riesgo:** crítico.
- **Estimación:** TBD.
- **Sprint:** Unassigned.

## Objetivo

Administrar de forma sensible y auditada el lifecycle completo de Stations y
sus bindings sin mezclarlo con la resolución runtime de PBI-024.

## Alcance

- Create, link, relink, unlink y revoke.
- Capability específica y reautenticación reforzada.
- Auditoría, concurrencia e invalidación de sesiones.
- UI/API administrativa sólo después de disponer de identidad y autorización.

## Fuera de alcance

- Trusted context runtime, hardware fingerprint como autoridad, MDM, inventario
  de dispositivos o administración de Tenant.

## Dependencias y criterios

Depende de PBI-024, PBI-034, PBI-026, PBI-035 y PBI-028. Toda mutación debe
fallar cerrada, preservar historia, invalidar contexto afectado y probar
aislamiento tenant/branch.

TL-01 resolvió el contexto previo a Station mediante
[ADR-015](../../decisions/proposed/ADR-015-tenant-administrative-control-plane.md).
La futura TL-07 debe reconciliar este PBI Draft con el Admin Context, el
challenge de alta entropía/single-use con TTL de 10 minutos, capabilities
explícitas y Level 2 con password reauth vigente 10 minutos para issue/revoke/
relink. Redemption revalida atómicamente issuer authority, estados y revisions
sin pedir password al equipo. Esta referencia no inicia PBI-031, no
lo convierte en PBI actual y no decide todavía si TL-07 lo materializa o lo
reemplaza mediante el workflow canónico.

## Próxima revisión

Antes de iniciar TL-07 o habilitar administración de Stations a usuarios del
Tenant; ADR-015 y `TLD-006` ya están resueltos, pero TL-07 requiere autorización
y readiness propios.
