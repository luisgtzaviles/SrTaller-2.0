## Problema

Elegir estructura y design system sin conocer aplicaciones/journeys puede recrear componentes duplicados o imponer una tecnología inadecuada.

## Valor esperado

Definir una estrategia consistente, accesible y mantenible para clientes web, separada de reglas de negocio.

## Alcance

- Comparar Next.js/React con alternativas pertinentes según superficies.
- Comparar la estrategia visual. Para V1 del cliente React/Vite actual quedó
  aprobada la combinación CSS custom properties + CSS Modules, sin Tailwind ni
  CSS-in-JS.
- Analizar rendering, caché tenant-scoped, accesibilidad, responsive y despliegue independiente.

## Fuera de alcance

- Crear Next.js, componentes, CSS, mockups o instalar dependencias.
- Aprobar apariencia, navegación o paridad móvil.

## Criterios de aceptación

- [x] La primera superficie materializada y su audiencia operativa están
  identificadas para la dirección visual V1.
- [x] ADR-006 documenta alternativas y límites con API central sin quedar
  aceptada.
- [x] La dirección V1 define ownership y prevención de componentes paralelos.
- [x] Accesibilidad y estados de UI se incorporan desde criterios, no como
  corrección tardía.
- [x] Producto, diseño y arquitectura revisaron la dirección V1 y su
  reconciliación; la estrategia web futura permanece pendiente.

## Dependencias

PBI-002, PBI-003, PBI-010 y respuestas sobre aplicaciones web.

## Riesgos

Caché cross-tenant; lógica de negocio duplicada; design system sin owner; asumir SSR o SPA sin necesidad.

## Preguntas abiertas

- ¿Qué clientes web se requieren y para quién?
- ¿Qué rendering y número de clientes web justificará la estrategia futura?
- ¿Qué idiomas aplican a cada superficie? WCAG 2.2 AA ya es el objetivo de
  diseño V1, no una certificación.

## Evidencia esperada

Matriz de superficies/requisitos, ADR revisado y principios de design system.

## Actualización por decisión Owner

- La dirección visual V1, el tenant accent, light/dark/system, responsive,
  accesibilidad y gobierno de CSS quedaron aprobados para documentación y
  preparación de PBI.
- Tailwind no se adopta en V1. CSS custom properties y CSS Modules aplican al
  cliente React/Vite materializado.
- Esta actualización no acepta Next.js ni resuelve rendering, caché, número de
  aplicaciones o despliegue futuro; ADR-006 conserva estado `Proposed`.
- [PBI-030](./PBI-030.md) materializa el candidato de implementación como
  `Draft`, sin autorización de inicio.
