# PBI-023 — Establish tenant-scoped persistence and migration foundation

## Estado

- **Estado:** `Ready`.
- **Ejecución:** no iniciada; autorización pendiente de revisión final.
- **Epic:** EPIC-001 — Engineering Foundation.
- **Tipo:** Technical foundation / Persistence / Security / Quality.
- **Riesgo:** alto, fail-closed.
- **Owner de ejecución:** Ingeniería.
- **Owners de control:** Arquitectura, Seguridad, Operaciones y Calidad.
- **Sprint:** Unassigned.
- **Estimación:** pendiente antes de compromiso; no se inventan puntos.

## Objetivo y valor

Crear la primera fundación persistente de R0: PostgreSQL 18.4 reproducible,
migraciones gobernadas y repositorios tenant-scoped que demuestren con dos
tenants sintéticos que el acceso cruzado falla, sin exponer API ni implementar
identidad, sesiones o negocio.

## Alcance

- Resolver y registrar DEC-050 antes de instalar migrador o crear migración.
- Ejecutar SPIKE-002 acotado antes de persistencia tenant-scoped.
- Materializar DEC051-C03/C04/C06 y DEC063-C02/C05/C06 antes de sus triggers.
- Aplicar DEC049-C01–C08 al alcance mínimo.
- Crear únicamente objetos base de tenant y la infraestructura necesaria para
  demostrar ownership, scope y constraints.
- Probar dos tenants, referencias cruzadas, omisión/conflicto de scope,
  commit/rollback y cleanup.
- Materializar fixtures sintéticos deterministas de DEC-052.
- Usar credenciales de test efímeras; no crear secretos de ambiente compartido.

## Exclusiones

- RLS, salvo nueva autorización posterior a SPIKE-003.
- HTTP/API, autenticación, PIN, sesión, roles, sucursal/estación runtime o UI.
- Datos reales, snapshot productivo, deploy o ambiente compartido.
- Reparaciones, clientes, inventario o cualquier regla de negocio.
- Decidir proveedor productivo, backup/restore o release.

## Dependencias y decisiones

- Satisfechas: H0 9/0, ADR-002/003/004/005/009, DEC-004/005/044/049/051/063.
- Incluidas en el PBI: DEC-006/007/008/050/052, SPIKE-002 y condiciones por
  trigger listadas en alcance.
- No requerida para este slice: resolución runtime de DEC-009; los tests
  inyectan un scope explícito y no lo presentan como contexto confiable HTTP.
- No existe decisión material pendiente fuera del alcance que autorice una
  elección irreversible de este PBI.

## Criterios de aceptación

- [ ] DEC-050 tiene decisión formal previa a la primera migración.
- [ ] SPIKE-002 tiene pregunta, timebox, evidencia, dictamen y cleanup.
- [ ] Riesgo DEC063-C02 y checklist DEC063-C05/C06 están materializados.
- [ ] PostgreSQL `18.4` real es reproducible, aislado y limpiable.
- [ ] Kysely/`pg` usan versiones exactas aprobadas antes de instalar.
- [ ] Cada objeto tiene owner y scope único; no existe repositorio genérico.
- [ ] Migraciones aplican desde cero, son deterministas y tienen estrategia
  forward/recuperación probada.
- [ ] Constraints y repositorios impiden lectura/escritura cross-tenant.
- [ ] Dos tenants sintéticos y casos de omisión/conflicto pasan.
- [ ] Transaction runner conserva la misma conexión y prueba commit/rollback.
- [ ] Errores de persistencia se traducen y sanitizan conforme DEC-044.
- [ ] Checker/gates rechazan imports, raw SQL y acceso excepcional no autorizado.
- [ ] Logs/evidencia no contienen SQL, secrets, PII ni rutas personales.
- [ ] Gates locales/CI aplicables, doble run y `git diff --check` pasan.
- [ ] No se agregó endpoint, auth, UI, negocio o deploy.

## Evidencia esperada y gates

- Migraciones, manifest de fixtures y PostgreSQL/version/lifecycle.

- Manifest canónico DEC-063 ligado a commit/PR.
- `pnpm run architecture`, typecheck, build, test, test:architecture, verify,
