# PBI-027 — Branch Timezone Minimum

## Estado

- **Estado:** Ready candidate / Ready for review; DoR y estimación pendientes.
- **Tipo:** Data / Application Foundation.
- **Owner:** Producto + Operaciones + Arquitectura + Ingeniería.
- **Riesgo:** alto.
- **Estimación:** TBD; no puede declararse `Ready` hasta existir acuerdo.
- **Sprint:** siguiente candidato de Sprint 01; no es PBI actual, no está
  iniciado ni autorizado.

## Objetivo

Conservar instantes autoritativos y presentar días/horas operativos usando la
timezone IANA explícita de la Branch, sin reescribir historia.

## Decisión Owner

- Autoridad temporal operativa: Branch.
- Tenant puede ofrecer un default de provisioning.
- Cada Branch conserva timezone IANA explícita, por ejemplo `America/Hermosillo`.
- Un offset fijo no es autoridad.

## Alcance

- Persistencia y validación de timezone por Branch.
- Separación entre instante autoritativo y zona de presentación.
- Contrato para cambio de timezone sin reescritura histórica.
- Casos de límites de día y operación multisucursal con reloj controlado.

## Fuera de alcance

- Calendarios, turnos, nómina, SLA, scheduling o UI final.
- Reportes comerciales completos.

## Dependencias

- Tenants/Branches persistentes ya integrados.
- DEC-037 queda resuelta por la decisión Owner del 2026-09-03.

## Criterios de aceptación

- Toda Branch operativa tiene timezone IANA válida.
- Instantes se conservan independientemente de la presentación.
- Cambiar la timezone no altera eventos históricos.
- Casos alrededor de medianoche y branches diferentes son reproducibles.
- Migración, fallback y rollback quedan definidos antes de implementación.

## Gate de preparación

Objetivo, scope y decisión de producto están resueltos. Falta estimación
acordada y revisión DoR completa; por ello permanece `Ready candidate / Ready
for review`, no `Ready` de implementación.
